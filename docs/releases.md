# Release notes

Every release body is generated by `pkgctl notes` from the assembled manifest,
the previous release tag and the recipe. `gh release create --generate-notes`
is not used: the shape is fixed, and every claim has a machine source.

## Template

````markdown
love 11.5-3 for Windows, x86-64-v3 (AVX2). 2D game framework for Lua.

## Upstream Changes
Upstream 11.5 is unchanged since 11.5-2. Changelog: https://github.com/love2d/love/releases/tag/11.5

## Packaging Changes
- `11.5-2` -> `11.5-3`; packaging only.
- LuaJIT is built with `zig cc` instead of the MSVC backend.

## Differences from upstream
- `/GL` + `/LTCG` for CMake-built code; upstream's release build does not
  enable link-time code generation.
- The VC++ runtime is not bundled (upstream ships `msvcp*.dll`); install the
  matching Redistributable.
- LuaJIT comes from `openresty/luajit2@93162f3` and is built with `zig cc`;
  upstream builds its vendored LuaJIT with MSVC.

## Verification
- Reproducibility: **L2** — A/B on windows-2025 produced identical archives;
  not verified across runner images.
- Archive: `love-11.5-3-amd64v3.zip` — 3,978,914 bytes, `sha256:2e862ad1…3acd`

Verify the attestation:

```bash
gh attestation verify love-11.5-3-amd64v3.zip \
  --repo nekrozis/buildsmith \
  --signer-workflow nekrozis/buildsmith/.github/workflows/package.yml \
  --source-digest <full 40-hex sha> \
  --source-ref refs/heads/main \
```

Runtime: Dynamic CRT; install the Microsoft Visual C++ Redistributable.
Built with: MSVC 14.51.36231 · zig 0.17.1 · windows-2025 (20261103.298.1)
````

## Rules

- The release title is `<name> <pkgver>-<pkgrel>`. The platform line stays in
  the body header and in the README; the title does not repeat it.
- `Upstream Changes` links the upstream release page for the pinned tag and
  never copies upstream prose. When `pkgver` does not change it says so.
- `Packaging Changes` is the delta since `<prev-tag>`: the version transition
  plus the commit subjects under `packages/<name>`. A `pkgrel` bump with no
  upstream change must explain itself here.
- `Differences from upstream` is `build.overrides` verbatim, and the section
  is omitted when that list is empty. Each entry has to name the upstream side;
  see `recipes.md`.
- `Verification` records the reproducibility level, the archive digest and a
  copy-pasteable attestation command with the full source digest. Smoke tests
  are a build gate and do not appear in the body.
- `Runtime` and `Built with` are one-line footers. Go, Rust and zig are exact
  pins; MSVC prints the toolset patch captured by `setup-msvc.ps1`, or the
  major bound when the manifest predates that capture.
- Headings and their order are fixed. `publish.yml` asserts the three mandatory
  headings before creating the draft.

## Generating

```bash
python tools/pkgctl.py notes 
  --manifest dist/love-11.5-3-amd64v3.manifest.json \
  --prev-tag love/v11.5-2 \
  --repo nekrozis/buildsmith \
  --source-digest <40-hex sha> \
  --source-ref refs/heads/main \
  --out notes.md --title-out title.txt \
```

`--prev-tag` is required for a rebuild; without it the body is an initial
build. The command reads the tag history, which is why the publish job checks
out with `fetch-depth: 0`.

## Backfilling existing releases

Do this before enabling immutable releases.

1. Download the release's `.manifest.json` asset.
2. Find the previous release tag for the same package (`gh release list`).
3. Read `--source-digest` and `--source-ref` from the attestation:
   `gh attestation verify <zip> --repo ... --format json`, then
   `certificate.sourceRepositoryDigest` and `sourceRepositoryRef`.
4. Generate the body with `pkgctl notes` and apply it:
   `gh release edit <tag> --notes-file notes.md [--title "$(cat title.txt)"]`.

The archived manifests predate the `msvc_toolset` capture, so their `Built
with` line falls back to the major bound until the package is rebuilt.
